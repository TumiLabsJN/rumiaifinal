# Stage 2.7 Classification Prompt - Comprehensive Critique & Refinement

> **Purpose**: Systematic refinement of Classification prompt for video content classification
> **Created**: 2025-01-28
> **Status**: In Progress - Section-by-Section Review

---

## Overview

This document critiques and refines the Stage 2.7 Classification prompt through 10 systematic audits. Each section presents 3 alternatives with recommendation and final decision.

**Prompt Context**:
- **Input**: Single video (transcript + caption + hashtags) + curated taxonomy from Stage 2.6
- **Output**: JSON with 22 fields (10 core + 12 caption_analysis subfields)
- **Model**: Claude 3 Haiku
- **Cost**: ~$0.001 per video (~$0.12 per hashtag for 120 videos)
- **Duration**: ~2-3 seconds per video

**Critique Sources**:
- Claude self-critique: 9 issues identified (5 critical, 4 medium)
- ChatGPT critique: 8 issues identified
- Combined total: 17 distinct concerns

## Section 1: System Message & Taxonomy Origin

**Current (First Draft)**:
```
You are an expert content classifier specializing in short-form video analysis. Your task is to accurately classify videos using a predefined taxonomy. Be objective and evidence-based: select classifications that best match the video content based on transcript, caption, and hashtags. When evidence is ambiguous, note lower confidence rather than forcing a classification.
```

**Questions**:
1. Should we add explicit reminder that taxonomy came from Stage 2.6 discovery? (ChatGPT Critique 1)
2. Should we warn against "semantic expansion" or reinterpretation of taxonomy labels?
3. How strong should the "don't force" language be?

**Decision**: ✅ Alternative B (Add Taxonomy Origin Reminder)

**Final System Message**:
```
You are an expert content classifier specializing in short-form video analysis. Your task is to accurately classify videos using a predefined taxonomy that was empirically discovered from real video data in this hashtag (Stage 2.6).

Be objective and evidence-based: select classifications that best match the video content based on transcript, caption, and hashtags. Use taxonomy categories EXACTLY as defined - do not reinterpret or expand their meaning. When evidence is ambiguous, note lower confidence rather than forcing a classification.
```

**Rationale**: Adds valuable context about taxonomy's empirical origin (addresses ChatGPT Critique 1). Explicit constraint "Use taxonomy categories EXACTLY as defined - do not reinterpret or expand" prevents semantic drift without over-engineering. Maintains "note lower confidence rather than forcing" escape valve. Adds ~30 tokens (~$0.00003/video, negligible). Balanced approach consistent with 2.6 Section 1 "Balanced Hybrid" philosophy.

## Section 2: Instruction Structure & Cognitive Load

**Current (First Draft)**:
Prompt has 7 sections in sequence:
1. Taxonomy (complete display)
2. Video Data (transcript/caption/hashtags)
3. Classification Instructions (categories 1-6)
4. Caption Analysis
5. Hashtag Strategy
6. Output Format
7. Final Instructions

**Questions**:
1. Is this structure too dense? (ChatGPT Critique 2, Claude Critique 7)
2. Should we split into 3 logical zones: Core Classification → Caption/Hashtag Analysis → Meta/Output?
3. Should we simplify taxonomy display (names only vs full definitions)?

**ChatGPT Suggestion**:
Split into 3 zones to reduce cognitive load:
- Zone 1: Core Classification (taxonomy-based, categories 1-6)
- Zone 2: Caption & Hashtag Analysis (linguistic analysis)
- Zone 3: Meta (confidence, note, output format)

**Decision**: ✅ Alternative B (3-Zone Structure)

**Final Structure**:
```
## ZONE 1: TAXONOMY & CORE CLASSIFICATION

### Provided Taxonomy
[Display complete taxonomy with definitions for all 6 categories]

### Video Data
[Transcript, caption, hashtags]

### Classification Task
Select the best-matching categories from the taxonomy above:
- Categories 1-2: Single selection (content_category, hook_strategy)
- Categories 3-6: Multiple selection (pain_points, keywords, drivers, tactics)

[Detailed selection instructions]

---

## ZONE 2: CAPTION & HASHTAG ANALYSIS

Analyze caption structure and hashtag strategy as a secondary task after completing Zone 1:
- Caption hook type, CTA presence/type, emoji usage, length
- Hashtag count, placement, categorization (broad/niche/branded)

[Detailed analysis instructions]

---

## ZONE 3: OUTPUT & CONFIDENCE

### Confidence Assessment
[Criteria for high/medium/low based on evidence quality]

### Output Format
[Complete JSON schema with all 22 required fields]

### Final Instructions
[Grounding rules, exact string matching, JSON-only output]
```

**Rationale**: 3-zone structure prevents two key failure modes: (1) Hallucination - Zone 1 creates "classification bubble" where LLM completes taxonomy matching BEFORE free-form analysis, reinforcing "select from taxonomy ONLY" constraint; (2) Misclassification - Separates taxonomy matching (Zone 1) from linguistic analysis (Zone 2), preventing caption sentiment from influencing core classification. Unlike 2.6 Discovery (single reasoning mode throughout), 2.7 has TWO reasoning modes: constrained taxonomy matching + free-form caption analysis. Zones provide cognitive separation that linear structure lacks. Keep full taxonomy definitions (not simplified) - accuracy depends on understanding category meanings. ~50 extra tokens for zone headers (~$0.00005/video) worth the structural constraint enforcement.

## Section 3: Core Classification Instructions (Single Selection)

**Current (First Draft)**:
```
### Categories 1-2: Single Selection
- **Content Category**: Select the ONE category that best describes the primary content format
- **Hook Strategy**: Select the ONE strategy that best describes how the video opens

If transcript is empty, use caption opening to determine hook strategy.
```

**Also states in Final Instructions**:
```
4. If no good match exists in taxonomy, select closest match and set confidence=low
...
Match content to taxonomy accurately. Do not force classifications.
```

**Critical Issue (Claude Critique 1 + ChatGPT Critique 4)**: These contradict each other!

**Questions**:
1. What should LLM do if video truly doesn't fit any taxonomy category?
2. Should we enforce EXACT string matching from taxonomy? (ChatGPT: "Do not paraphrase or shorten")
3. Should we allow "unknown" or "other" category as escape valve? (Claude Critique 5)

**Decision**: ✅ Alternative A (Force Closest Match with Transparency)

**Final Instructions**:
```
### Categories 1-2: Single Selection (REQUIRED)

**Content Category**: Select exactly ONE category that best describes the primary content format.

**Hook Strategy**: Select exactly ONE strategy that best describes how the video opens.

**IMPORTANT**: You MUST copy the category name EXACTLY as written in the taxonomy. Do not paraphrase, abbreviate, or modify the string. Mismatched spelling or underscores will cause system errors.

**If no perfect match exists**: Select the closest matching category from the taxonomy. Set confidence=low and document the mismatch in the note field (e.g., "Video is comedy skit, closest match is wellness_practice").

**String Matching**: Copy category names character-for-character from taxonomy above.
```

**Rationale**: Removes contradiction by explicitly requiring selection (categories 1-2 must have non-null values for contrastive analysis). Addresses ChatGPT Critique 4 with "MUST copy EXACTLY" + "Mismatched spelling causes system errors". Transparency mechanism: confidence=low + explanatory note flags forced matches for curator review. Reality: some videos won't perfectly fit taxonomy (outliers happen) - forcing with transparency better than null values (breaks analysis) or "other" category (breaks taxonomy logic). If many confidence=low videos, signals taxonomy needs refinement in 2.6. Aligns with design philosophy: 2.6 discovers patterns comprehensively, 2.7 maps videos to patterns (forced matches inevitable but flagged).

## Section 4: Multi-Select Instructions (Categories 3-6)

**Current (First Draft)**:
```
### Categories 3-6: Multiple Selection (0-N)
- **Audience Pain Points**: Select ALL pain points mentioned or implied in the content
- **Trending Keywords**: Select ALL keywords mentioned or implied (topics, methods, concepts)
- **Engagement Drivers**: Select ALL tactics that make this content compelling
- **Content Tactics**: Select ALL presentation styles or formats used

Return empty arrays `[]` if none apply. Do not select items that are not clearly present.
```

**Questions**:
1. Should we add explicit GROUNDING RULE like in 2.6 Discovery? (Claude Critique 6)
2. What does "clearly present" mean - should we define this?
3. Should we allow "implied" or require "explicitly mentioned"?

**Claude Critique 6**: Missing grounding requirement. 2.6 Discovery had "traceable to at least 3 transcripts". Classification should have equivalent: "Only select items explicitly mentioned OR strongly implied."

**Decision**: ✅ Alternative B (Balanced Grounding - Explicit OR Strongly Implied)

**Final Instructions**:
```
### Categories 3-6: Multiple Selection (0-N)

Select ALL applicable items from the taxonomy that are clearly present in the video:

- **Audience Pain Points**: Problems explicitly stated OR strongly implied from solutions discussed
- **Trending Keywords**: Topics/methods explicitly mentioned OR clearly central to the content
- **Engagement Drivers**: Tactics described OR evident from how creator speaks
- **Content Tactics**: Presentation styles explicitly mentioned OR observable from transcript patterns

**GROUNDING RULE**: Only select items that are:
1. **Explicitly mentioned**: Can quote a direct phrase (e.g., "I had bloating")
2. **Strongly implied**: Clear evidence from context (e.g., "I started X and it went away" → X addresses implied problem)

If uncertain whether implication is strong enough, do NOT select. Empty arrays `[]` are acceptable.

**Evidence requirement**: For each selection, you should be able to explain WHY it's selected with specific evidence from transcript or caption.
```

**Rationale**: Addresses Claude Critique 6 by adding explicit grounding rule parallel to 2.6 Discovery. Consistent with 2.6 Section 5 decision (Alternative D - Grounded Discovery with Flexibility): "mentioned OR IMPLIED" allowed in discovery, same philosophy in classification. Two clear evidence types: (1) Explicitly mentioned - can quote phrase, (2) Strongly implied - clear contextual evidence. "Strong" qualification prevents weak inference. Balances false negatives (missing patterns) vs false positives (wrong patterns). Example: "lost 15 pounds" → strongly implies weight_loss pain point. Human curation safety net: false positives easy to fix during review, false negatives costly (missing actionable patterns). Evidence requirement check: LLM must be able to explain WHY selected with specific evidence.

## Section 5: Confidence Scoring

**Current (First Draft)**:
```
confidence: high = clear match, medium = ambiguous, low = forced fit
```

**Questions**:
1. Are these criteria too vague? (Claude Critique 8, ChatGPT Critique 3)
2. Should we add operational definitions tied to evidence sources?
3. Should we make confidence mandatory vs optional?

**ChatGPT Suggestion**:
```
high = transcript + caption align perfectly, clear taxonomy match
medium = transcript partially supports classification, some inference needed
low = classification inferred from partial clues (e.g., only hashtags available)
```

**Decision**: ✅ Alternative B (Match Quality + Evidence Hybrid)

**Final Instructions**:
```
### Confidence Assessment

Assign confidence based on two factors: (1) How well video matches taxonomy, (2) Quality of evidence

**high**:
- Video clearly matches selected categories (no ambiguity in taxonomy fit)
- Strong evidence from transcript and/or caption
- All selections can be justified with explicit phrases or strong implications

**medium**:
- Video partially matches taxonomy OR selection required inference
- Evidence from transcript OR caption, but not both aligning
- Some selections based on reasonable but not explicit evidence

**low**:
- Forced match for required categories (no perfect taxonomy fit)
- Limited evidence (empty transcript, minimal caption)
- Selections based on weak inference or hashtags alone

**Tie-breakers**:
- If transcript unavailable but caption is rich → can be medium (not automatically low)
- If perfect taxonomy match but only hashtags available → medium (good match, weak evidence)
```

**Rationale**: Addresses both Claude Critique 8 and ChatGPT Critique 3 by providing operational definitions with two-factor model: (1) Taxonomy match quality - does video clearly fit selected categories? (Section 3 concern about forced matches), (2) Evidence quality - do we have strong data? (ChatGPT's evidence-source concern). More nuanced than single-factor approaches. Covers edge cases with tie-breaker rules: rich caption without transcript can still be medium. Connects to Section 3: forced match = low confidence (explicit). Connects to Section 4: weak inference impacts confidence level. Real-world insight: confidence depends on BOTH taxonomy fit AND evidence strength. Examples: (a) Recipe video, aligned transcript+caption → high, (b) Comedy skit forced into wellness_practice → low (forced match), (c) Clear wellness video, empty transcript, detailed caption → medium (good match, partial evidence). Critical for Stage 7 contrastive analysis quality.

## Section 6: Caption Analysis Fields

**Current (First Draft)**:
```
### Caption Analysis
Analyze the caption structure independently:
- **Hook Type**: How does the caption open? (statement, question, command, teaser, statistic, contradiction)
- **CTA Type**: What call-to-action is used? (link_in_bio, save_post, comment, follow, share, tag_friend, none)
- **Emoji Usage**: How many emojis are used? (none: 0, light: 1-2, moderate: 3-5, heavy: 6+)
- **Caption Length**: How long is the caption? (short: <50 chars, medium: 50-150, long: 150+)
```

**Multiple Issues**:
1. **Arbitrary thresholds** (Claude Critique 2): Why is "light" 1-2 emojis? Why "short" <50 chars?
2. **Undefined terms** (ChatGPT Critique 2): What is "teaser" vs "statement"? What is "contradiction"?
3. **Over-engineered** (Claude Critique 9): 12 subfields may be too many, increases error rate
4. **Different reasoning modality** (ChatGPT Critique 6): Caption analysis is linguistic, not pattern classification
5. **Redundant fields**: caption_cta_present can be derived from caption_cta_type != none

**Questions**:
1. Should we simplify to core fields only (hook type, CTA type, counts)?
2. Should we provide one-line examples for each hook type?
3. Should we remove arbitrary thresholds and use simpler categories?

**Decision**: ✅ Alternative C (Middle Ground - Simplify Categorizations, Keep Useful Fields)

**Final Instructions**:
```
### ZONE 2: CAPTION & HASHTAG ANALYSIS

Analyze caption structure and hashtag strategy as a secondary task after completing Zone 1.

**Caption Hook Type**: How does the caption open? (first 5-10 words)
- statement: Declarative ("This changed my life", "Best product ever")
- question: Interrogative ("Did you know?", "Have you tried?")
- command: Imperative ("Try this now", "Follow for more")
- teaser: Creates curiosity ("You won't believe…", "Wait till the end")

**Call-to-Action**:
- caption_cta_type: link_in_bio, save_post, comment, follow, share, tag_friend, none
- brand_mention_present: Does caption mention a brand/product? (true/false)
- influencer_tag_present: Does caption tag another creator? (true/false)

**Caption Metrics** (simplified levels):
- emoji_usage: none (0), some (1-4), many (5+)
- caption_length: short (<100 chars), long (100+ chars)

**Hashtag Analysis**:
- hashtag_count: Total number of hashtags (integer)
- hashtag_placement: end (all at end), mixed (throughout caption), none

**Note**: Do not attempt to categorize hashtags as broad/niche/branded - this requires view count data not available.
```

**Rationale**: Addresses all 5 issues: (1) Simplified thresholds to intuitive categories (none/some/many emojis, short/long at 100 chars = TikTok's visible preview length), (2) All hook types defined with inline examples, removed vague types (statistic, contradiction), (3) Reduced from 13→9 fields (31% reduction), (4) Separated in Zone 2 as secondary linguistic task after core classification, (5) Removed caption_cta_present (redundant - derivable from cta_type != none). Removes unreliable hashtag broad/niche/branded categorization (heuristic without view count data) - explicitly acknowledges limitation. Keeps valuable fields for Stage 7: brand_mention, influencer_tag (useful for contrastive analysis). Simplified emoji levels (3 instead of 4) and length levels (2 instead of 3) use rounder, more intuitive boundaries. Hook types reduced from 6→4, keeping most common patterns with clear examples. Trade-off: loses hashtag strategy data but this was unreliable anyway. 9 fields is manageable - not minimal but not over-engineered.

**Questions**:

2. Should we use keyword-based rules (if contains brand name → branded)?

**Final Instructions** (from Section 6):
```
**Hashtag Analysis**:
- hashtag_count: Total number of hashtags (integer)
- hashtag_placement: end (all at end), mixed (throughout caption), none

**Note**: Do not attempt to categorize hashtags as broad/niche/branded - this requires view count data not available.
```

**Rationale**: Section 6 decision (Alternative C) removed the hashtag_strategy.broad_count, hashtag_strategy.niche_count, and hashtag_strategy.branded_count fields entirely. Addresses all 3 issues: (1) No more heuristic categorization - LLM doesn't have TikTok view count data to reliably determine if hashtag is "broad" or "niche", (2) No boundary ambiguity - removed the categorization entirely, (3) No multi-category rule needed - no categorization to apply. Keep only objective, countable fields: total hashtag count (integer) and placement (where hashtags appear in caption). Explicit note acknowledges limitation: "this requires view count data not available". Trade-off: Loses hashtag strategy insights for Stage 7, but unreliable data is worse than no data. If hashtag strategy becomes important, can add external hashtag popularity lookup in future (Python post-processing with TikTok API or hashtag database).

## Section 8: Transcript Fallback Handling

**Current (First Draft)**:
```
**Transcript**:
{transcript['text'] if transcript['available'] else "(No transcript available - classify using caption and hashtags)"}

If transcript is empty, use caption opening to determine hook strategy.
```

**Issues**:
1. **Hook strategy fallback is ambiguous** (Claude Critique 4): Caption opening ≠ video opening. Caption "Have you tried this?" might accompany video opening with "This changed my life"
2. **No handling for conflicting evidence** (Claude Critique 10): What if transcript says instructional but caption says promotional?
3. **Note field is hardcoded**: Only handles empty transcript case, not other degraded scenarios

**Questions**:
1. Should we add "unknown" hook strategy for videos without transcripts?
2. Should we establish evidence priority hierarchy (transcript > caption > hashtags)?
3. Should note field allow dynamic messages for low confidence?

**Decision**: ✅ Alternative C (Force with Transparency + Evidence-Based Note Field)

**Final Instructions**:
```
**Evidence Handling & Fallback Logic**:

**Hook Strategy** (required single selection):
- **Primary**: Use transcript opening (first 5-10 words spoken)
- **Fallback**: If transcript empty, use caption opening (first 5-10 words written)
- **Caveat**: Caption opening may not reflect actual video opening - this is acceptable as "best available evidence"

**Content Category** (required single selection):
- **Primary**: Classify from full transcript + caption alignment
- **Fallback**: If transcript empty, classify from caption + hashtags only

**Note Field** (dynamic context for low-confidence scenarios):
- Empty transcript → "Classified from caption/hashtags only - no transcript available"
- Conflicting evidence → "Transcript suggests X, caption suggests Y - selected X (transcript priority)"
- Forced match → "No perfect taxonomy match, selected closest: [category_name]"
- Multiple issues → Combine messages: "No transcript + forced match to [category]"

**Evidence Priority** (transparent but enforced):
When evidence conflicts: transcript > caption > hashtags. Document conflicts in note field.
When evidence is weak: still make best-effort classification, but set confidence=low and explain in note.
```

**Rationale**: Maintains required fields for Stage 7 contrastive analysis (no null values, no special categories) while being fully transparent about evidence limitations via dynamic note field. Acknowledges caption opening ≠ video opening but accepts it as pragmatic fallback - flagged via transcript_available=false (machine-readable for filtering) + note field (human-readable for curator review). Evidence priority hierarchy prevents hallucination (must use actual transcript/caption/hashtags). Handles all edge cases: empty transcript, conflicting evidence, forced matches, multiple degraded scenarios. Note field is composable - can combine multiple issues. Aligns with Section 3 decision (force with transparency) and Section 5 (confidence=low flags weak evidence). Practical reality: many TikTok videos lack transcripts (music videos, visual-only content) - blocking these reduces dataset. Caption hook may correlate with video hook (creators often align them). Stage 7 can stratify by transcript_available if source matters for analysis. Trade-offs accepted: some hook strategies inferred from caption (not video), some classifications based on weak evidence - but both transparently flagged.

## Section 10: Final Instructions & Anti-Hallucination

**Current (First Draft)**:
```
## FINAL INSTRUCTIONS

1. Base ALL classifications on evidence in the video data - do not invent content
2. Select ONLY from the provided taxonomy - do not create new categories
3. Empty transcript? Classify using caption and hashtags only, set transcript_available=false
4. If no good match exists in taxonomy, select closest match and set confidence=low
5. Return valid JSON only - no commentary, explanations, or additional text outside the JSON structure

Match content to taxonomy accurately. Do not force classifications.
```

**Critical Issues**:
1. **Direct contradiction** (Claude Critique 1): Line 4 says "select closest match" but last line says "Do not force classifications"
2. **Missing exact-match enforcement** (ChatGPT Critique 4): Should explicitly state "Copy category names EXACTLY as written. Do not paraphrase or shorten."
3. **Weak anti-hallucination** compared to 2.6: 2.6 had "DO NOT make up patterns to fill categories. Quality over quantity." Should we strengthen?

**Questions**:
1. Should we remove contradictory instruction #4?
2. Should we add: "Mismatched spelling or underscores will cause system error"?
3. Should we add grounding reminder: "Only select items explicitly mentioned or strongly implied"?

**ChatGPT Suggestion**:
```
You must copy category names EXACTLY as written in the taxonomy. Do not paraphrase or shorten. Mismatched spelling or underscores will cause system error.

If uncertain, choose the closest exact string from the taxonomy list provided.
```

**Decision**: ✅ Alternative D (Hybrid - Checklist + Critical Additions)

**Final Instructions**:
```
## FINAL INSTRUCTIONS

Before submitting, verify all requirements are met:

### Critical Requirements (System Errors)
✓ **Exact Strings**: Copy category names character-for-character from taxonomy (e.g., "wellness_practice" NOT "wellness")
   - Mismatched spelling or underscores will cause system error
✓ **Complete Schema**: All 12 fields present (see Section 9)
✓ **JSON Only**: No text outside JSON structure

### Classification Quality
✓ **Evidence-Based**: All selections traceable to transcript/caption/hashtags - do not invent patterns
   - Quality over quantity: empty arrays [] better than wrong selections
✓ **Closest Match**: If perfect taxonomy match unclear, select closest category and set confidence=low
✓ **Note Field**: Explain when confidence=low (forced match, missing transcript, conflicts)
✓ **Evidence Priority**: transcript > caption > hashtags (see Section 8)

Your classifications feed Stage 7 contrastive analysis - accuracy is critical.
```

**Rationale**: Hybrid approach balances conciseness (~90 tokens) with completeness. Uses checklist format (easy to verify) with 2-tier structure (Critical vs Quality) for prioritization. Resolves Claude Critique 1 contradiction by removing "Do not force classifications" and replacing with "select closest category and set confidence=low" (consistent with Sections 3, 5, 8). Addresses ChatGPT Critique 4 with explicit "Copy character-for-character" + "system error" warning. Strengthens anti-hallucination with "quality over quantity" language from Stage 2.6 Discovery + "do not invent patterns". Stakes explained: "Stage 7...accuracy critical" emphasizes downstream impact. Evidence priority made explicit. Critical Requirements section catches system-breaking errors (wrong strings, missing fields, non-JSON). Classification Quality section ensures accuracy (grounding, forced match handling, transparency). More concise than Alternative C (150 tokens) while addressing gaps in Alternative B (missing contradiction resolution, no anti-hallucination language, no stakes). Best balance for preventing hallucination (grounding + quality over quantity) and misclassification (exact strings + closest match with low confidence) while allowing discovery (forced match acceptable with transparency).

### ZONE 3: OUTPUT & CONFIDENCE

**Evidence Handling & Fallback Logic**

**Hook Strategy** (required single selection):
- **Primary**: Use transcript opening (first 5-10 words spoken)
- **Fallback**: If transcript empty, use caption opening (first 5-10 words written)
- **Caveat**: Caption opening may not reflect actual video opening - this is acceptable as "best available evidence"

**Content Category** (required single selection):
- **Primary**: Classify from full transcript + caption alignment
- **Fallback**: If transcript empty, classify from caption + hashtags only

**Note Field** (dynamic context for low-confidence scenarios):
- Empty transcript → "Classified from caption/hashtags only - no transcript available"
- Conflicting evidence → "Transcript suggests X, caption suggests Y - selected X (transcript priority)"
- Forced match → "No perfect taxonomy match, selected closest: [category_name]"
- Multiple issues → Combine messages: "No transcript + forced match to [category]"

**Evidence Priority** (transparent but enforced):
When evidence conflicts: transcript > caption > hashtags. Document conflicts in note field.
When evidence is weak: still make best-effort classification, but set confidence=low and explain in note.

---

**Confidence Assessment**

Assign confidence based on two factors: (1) How well video matches taxonomy, (2) Quality of evidence

**high**:
- Video clearly matches selected categories (no ambiguity in taxonomy fit)
- Strong evidence from transcript and/or caption
- All selections can be justified with explicit phrases or strong implications

**medium**:
- Video partially matches taxonomy OR selection required inference
- Evidence from transcript OR caption, but not both aligning
- Some selections based on reasonable but not explicit evidence

**low**:
- Forced match for required categories (no perfect taxonomy fit)
- Limited evidence (empty transcript, minimal caption)
- Selections based on weak inference or hashtags alone

**Tie-breakers**:
- If transcript unavailable but caption is rich → can be medium (not automatically low)
- If perfect taxonomy match but only hashtags available → medium (good match, weak evidence)
