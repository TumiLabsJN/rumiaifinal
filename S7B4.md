## Bug Description

### Issue Summary

Creator-facing recommendations in Stage 7 outputs use normalized values [0, 1] without units or context, making them unactionable. Creators cannot implement recommendations like "0.03 scene_count" or "0.58 object_count" because they don't know if these are raw counts, percentages, or normalized ML values.

### Current Behavior

```json
"step_by_step_template": [
  "Hook (0-3s): Single sustained shot, minimal cuts (0.03 scene_count), extended scene duration (0.97)",
  "Middle_1 (3-8s): Burst of visual complexity (0.58 object_count), elevated energy (0.31)",
  "Middle_2-4 (8-23s): Maintain high verbal coverage (0.98-1.00), consistent information delivery (0.64-0.70 word_count)"
]
```

**Creator Confusion**:
- `0.03 scene_count` → Is this 0.03 scenes (impossible)? Or 3% of max? Or a normalized ML value?
- `0.58 object_count` → Is this 0.58 objects (impossible)? Or 58% of videos? Or a normalized value?
- `0.64-0.70 word_count` → Is this 0.64 words (impossible)? Or 64-70% of max? Or a normalized range?

### Expected Behavior

```json
"step_by_step_template": [
  "Hook (0-3s): Single sustained shot, minimal cuts (1 scene), extended scene duration (2.8 seconds)",
  "Middle_1 (3-8s): Burst of visual complexity (7 objects), elevated energy (moderate)",
  "Middle_2-4 (8-23s): Maintain high verbal coverage (98-100%), consistent information delivery (45-52 words)"
]
```

**Clear for Creators**: Raw values with units that can be directly implemented.

## Why This Bug Is NOT Contained to Stage 7

### Misconception: "This is a Stage 7 display issue"

**False Assumption**: The bug appears in Stage 7 outputs, so it must be a Stage 7-only problem.

**Reality**: This bug spans **4 stages** (Stages 4, 5, 6, and 7) with origins in Stage 4.

### Complete Bug Lifecycle

#### Stage 4: Bug Origin (Normalization)

**File**: `rumiai_v2/processors/feature_transformation.py`

**What Happens**:
- Raw features (e.g., 3 scenes, 12 words) are transformed to [0,1] range
- Log1p applied to 11 features for variance stabilization
- MinMaxScaler applied to all 18 features for K-Means compatibility
- Scalers saved to `{window}_scalers.pkl`

**Bug Introduction**: Features lose human interpretability (3 scenes → 0.52).

**Why This Happens**: K-Means requires normalized features for distance calculations. This is **correct ML practice**.

#### Stage 5: Bug Propagation (K-Means Training)

**File**: `rumiai_v2/processors/model_training.py`

**What Happens**:
- K-Means clustering performed on normalized features
- Cluster centroids are in normalized space [0,1]
- Centroids saved to `{window}_kmeans_analysis.json`

**Bug Propagation**: Centroids inherit normalized values from Stage 4 (0.52, 0.58, 0.97).

**Why This Happens**: K-Means operates in transformed feature space. This is **correct ML practice**.

#### Stage 6: Parallel Path (RF Uses Raw Values)

**File**: `ml_pipeline/stage6_analysis/ml_analysis_generation.py`

**What Happens**:
- Random Forest trained on **raw features** (not normalized)
- RF feature importance calculated on raw scale
- `top_performer_avg` and `bottom_performer_avg` are raw values

**No Bug Here**: RF pipeline correctly uses raw values because tree-based models don't require normalization.

**Key Insight**: Stage 6 (RF) and Stage 5 (K-Means) use **different feature spaces**. K-Means uses normalized, RF uses raw.

#### Stage 7: Bug Manifestation (LLM Outputs)

**Files**:
- `ml_pipeline/stage7_llm_analysis/stage7_prompts.py` (Phase 1)
- `ml_pipeline/stage7_llm_analysis/stage7_prompts.py` (Phase 2)

**What Happens**:
- **Phase 1**: LLM receives K-Means centroids (normalized) → generates defining_features with normalized values
- **Phase 2**: LLM reads Phase 1 outputs (normalized) → generates step_by_step_template with normalized values

**Bug Manifestation**: Normalized values reach creator-facing outputs without denormalization.

**Why This Happens**: Stage 7 doesn't know that K-Means centroids are normalized. It treats them as raw values.

**Why This Works**:

**Key Insight**: The boundary between ML space (normalized) and human space (raw) should be **Stage 7 Phase 1** - right before data goes to LLM for human consumption.

## Root Cause Analysis

### Direct Cause

**Stage 7 Phase 1** passes K-Means centroids to LLM without denormalization.

**Code Location**: `ml_pipeline/stage7_llm_analysis/stage7_prompts.py:build_phase1_prompt()`

```python
# Current code (line ~150)
kmeans_analysis = load_json(f'{bucket_path}/ml_analysis/{window}_kmeans_analysis.json')

for cluster in kmeans_analysis['clusters']:
    centroid = cluster['centroid']  # ← Normalized values [0,1]

    # Pass to LLM prompt (normalized values go as-is)
    prompt += f"Centroid: {json.dumps(centroid)}"
```

**Problem**: `centroid` contains normalized values (0.52, 0.58, 0.97) which LLM includes verbatim in defining_features.

### Contributing Factors

1. **Stage 4 Normalization** (necessary for K-Means)
   - Log1p + MinMaxScaler transforms features to [0,1]
   - Creates interpretability gap between ML space and human space

2. **Stage 5 K-Means Training** (operates in normalized space)
   - Centroids calculated on normalized features
   - Centroids inherit [0,1] range from Stage 4

3. **Stage 7 Phase 1** (no denormalization logic)
   - Treats normalized centroids as if they were raw values
   - LLM has no context that values are normalized

4. **Stage 7 Phase 2** (inherits from Phase 1)
   - Reads Phase 1 outputs which already contain normalized values
   - Propagates normalized values into step_by_step_template

### Why This Wasn't Caught Earlier

1. **ML Pipeline Works Correctly**: K-Means clustering produces valid results. The bug is in human presentation, not ML logic.

2. **LLM Adds Descriptive Text**: LLM writes "moderate person count (0.40 range)" which sounds plausible even though 0.40 is normalized.

3. **No Direct User Feedback**: Creators haven't used the system yet to report confusion about normalized values.

4. **Test Data Characteristics**: With trending hashtag (#test_vitamin), most features are in 0.3-0.7 range which could be mistaken for percentages.

### Denormalization Logic

#### Formula

```python
def denormalize_feature(normalized_val, feature_name, scaler):
    """
    Reverse Stage 4 transformation to get raw value.

    Stage 4 transformation:
      raw → log1p → MinMaxScaler [0,1] → normalized

    Reverse transformation:
      normalized → inverse MinMaxScaler → expm1 → raw

    Args:
        normalized_val: float in [0,1]
        feature_name: str, feature name (e.g., 'scene_count')
        scaler: MinMaxScaler object from {window}_scalers.pkl

    Returns:
        raw_val: float, denormalized value with original units
    """
    # Step 1: Reverse MinMaxScaler [0,1] → log space
    log_val = normalized_val * (scaler.data_max_[0] - scaler.data_min_[0]) + scaler.data_min_[0]

    # Step 2: Reverse log1p (if feature was log-transformed)
    if feature_name in LOG_SCALE_FEATURES:
        raw_val = np.expm1(log_val)  # exp(x) - 1
    else:
        raw_val = log_val

    return raw_val
```

#### Example Transformations

**Log-Transformed Feature** (scene_count):
```python

raw: 3 scenes
  → log1p: ln(1+3) = 1.386
  → MinMax: (1.386 - 0.0) / (1.609 - 0.0) = 0.86
normalized: 0.86

# Stage 7: normalized → raw (PROPOSED FIX)
normalized: 0.86
  → inverse MinMax: 0.86 * (1.609 - 0.0) + 0.0 = 1.383
  → expm1: exp(1.383) - 1 = 2.98
raw: 3.0 scenes ✅
```

**Direct MinMax Feature** (speech_coverage):
```python
# Stage 4: raw → normalized
raw: 85% coverage
  → MinMax: (0.85 - 0.0) / (1.0 - 0.0) = 0.85
normalized: 0.85

# Stage 7: normalized → raw (PROPOSED FIX)
normalized: 0.85
  → inverse MinMax: 0.85 * (1.0 - 0.0) + 0.0 = 0.85
```

```python
import joblib
from pathlib import Path

def load_scalers(bucket_path: str, window: str) -> dict:
    """
    Load MinMaxScaler objects for a window.

    Args:
        bucket_path: Path to bucket directory
        window: Window name (e.g., 'hook', 'middle_1', 'closing')

    Returns:
        dict: Scaler metadata with structure:
            {
                'scalers': {feature_name: MinMaxScaler, ...},
                'constant_features': [feature_names with zero variance]
            }

    Example:
        scalers = load_scalers('bucket_18-33s', 'hook')
        scene_scaler = scalers['scalers']['scene_count']
    """
    scaler_path = Path(bucket_path) / 'ml_analysis' / f'{window}_scalers.pkl'

    if not scaler_path.exists():
        logger.warning(f"Scaler file not found: {scaler_path}")
        return {'scalers': {}, 'constant_features': []}

    try:
        scalers = joblib.load(scaler_path)
        logger.debug(f"Loaded {len(scalers['scalers'])} scalers from {scaler_path}")
        return scalers
    except Exception as e:
        logger.error(f"Failed to load scalers from {scaler_path}: {e}")
        return {'scalers': {}, 'constant_features': []}
```

#### 1.3: Create Denormalize Feature Function

```python
import numpy as np

def denormalize_feature(normalized_val: float, feature_name: str, scaler) -> float:
    """
    Reverse Stage 4 normalization to get raw value.

    Stage 4 transformation:
      raw → log1p (if LOG_SCALE) → MinMaxScaler [0,1] → normalized

    Reverse transformation:
      normalized → inverse MinMaxScaler → expm1 (if LOG_SCALE) → raw

    Args:
        normalized_val: Normalized value in [0,1]
        feature_name: Feature name (e.g., 'scene_count')
        scaler: MinMaxScaler object from scalers.pkl

    Returns:
        raw_val: Denormalized value with original units

    Example:
        # scene_count (log-transformed)
        raw = denormalize_feature(0.86, 'scene_count', scaler)
        # Returns: 3.0 scenes

        # speech_coverage (direct scale)
        raw = denormalize_feature(0.85, 'speech_coverage', scaler)
        # Returns: 0.85 (85%)
    """
    # Step 1: Reverse MinMaxScaler [0,1] → log space (or raw space for non-log features)
    data_range = scaler.data_max_[0] - scaler.data_min_[0]

    if data_range == 0:
        # Constant feature (all values same)
        return scaler.data_min_[0]

    log_or_raw = normalized_val * data_range + scaler.data_min_[0]

    # Step 2: Reverse log1p if feature was log-transformed
    if feature_name in LOG_SCALE_FEATURES:
        raw_val = np.expm1(log_or_raw)  # exp(x) - 1
    else:
        raw_val = log_or_raw

    return raw_val
```

#### 1.4: Create Denormalize Centroid Function

```python
def denormalize_centroid(centroid: dict, scalers: dict) -> dict:
    """
    Denormalize all features in a K-Means centroid.

    Args:
        centroid: Normalized centroid from K-Means
            {
                'scene_count_scaled': 0.86,
                'word_count_scaled': 0.64,
                'shortest_scene_scaled': 0.29,
                ...
            }
        scalers: Scaler metadata from load_scalers()
            {
                'scalers': {feature_name: MinMaxScaler, ...},
                'constant_features': [...]
            }

    Returns:
        denormalized_centroid: Centroid with raw values
            {
                'scene_count': 3.0,
                'word_count': 45.0,
                'shortest_scene': 0.87,
                ...
            }

    Example:
        scalers = load_scalers('bucket_18-33s', 'hook')
        raw_centroid = denormalize_centroid(cluster['centroid'], scalers)
    """
    denormalized = {}

    for feature_key, normalized_val in centroid.items():
        # Remove '_scaled' suffix to get base feature name
        feature_name = feature_key.replace('_scaled', '')

        # Check if scaler exists for this feature
        if feature_name not in scalers['scalers']:
            # Feature not in scalers (might be categorical or unchanged)
            denormalized[feature_name] = normalized_val
            continue

        # Denormalize using scaler
        scaler = scalers['scalers'][feature_name]
        raw_val = denormalize_feature(normalized_val, feature_name, scaler)

        denormalized[feature_name] = raw_val

    return denormalized
```

#### 1.5: Create Format Value Function

```python
def format_feature_value(feature_name: str, raw_val: float) -> str:
    """
    Format raw value with appropriate unit and precision.

    Args:
        feature_name: Feature name (e.g., 'scene_count')
        raw_val: Raw denormalized value

    Returns:
        formatted_str: Human-readable string with unit

    Examples:
        format_feature_value('scene_count', 3.2) → "3 scenes"
        format_feature_value('shortest_scene', 2.84) → "2.8 sec"
        format_feature_value('speech_coverage', 0.85) → "85%"
    """
    # Count features: round to integer
    if feature_name in ['scene_count', 'word_count', 'gesture_count',
                        'object_count', 'person_count', 'overlay_unique_count']:
        formatted_val = f"{int(round(raw_val))}"

    # Time features: 1 decimal place
    elif feature_name in ['shortest_scene', 'longest_scene']:
        formatted_val = f"{raw_val:.1f}"

    # Percentage features: convert to %
    elif feature_name in ['speech_coverage', 'eye_contact_rate']:
        formatted_val = f"{int(raw_val * 100)}"

    # Ratio/score features: 2 decimal places
    else:
        formatted_val = f"{raw_val:.2f}"

    # Add unit
    unit = FEATURE_UNITS.get(feature_name, '')
    if unit:
        return f"{formatted_val} {unit}"
    else:
        return formatted_val
```
