# Stage 7 LLM Prompts - Current Implementation

## Overview

Stage 7 uses a two-phase approach:
- **Phase 1**: Analyze each temporal window individually (hook, middle_1, etc.)
- **Phase 2**: Synthesize cross-window patterns to identify "Winning Formulas"

---

## Phase 1 Prompt (Window Analysis)

**Purpose**: Analyze K-Means clusters and RF feature importance for a single temporal window

**Mode-Specific Behavior**:
- **CONTRASTIVE Mode**: Includes RF feature importance, RF alignment scores, bimodal pattern analysis
- **TOP Mode**: K-Means only, no RF references, focuses on common patterns among top performers

**Prompt Location**: Generated by `build_phase1_prompt()` in `stage7_prompts.py:266`

**Key Sections**:
1. Task description (mode-specific)
2. RF Feature Importance (CONTRASTIVE only) - Top 10 features with bimodal patterns
3. K-Means Clusters (3 clusters) - Centroid values, high-contrast features
4. RF Alignment (CONTRASTIVE only) - Which cluster features match RF top predictors
5. Cluster Size Context - How to frame dominant vs niche strategies
6. Output Requirements - JSON schema with 3 cluster analyses

**Example Length**: ~9,000 characters for hook window in CONTRASTIVE mode

**Full Prompt**: See `/tmp/phase1_contrastive_prompt.txt`

---

## Phase 2 Prompt (Cross-Window Synthesis)

**Purpose**: Synthesize Phase 1 window analyses into complete video journey "Winning Formulas"

**Scenario-Based Logic**:
- **Scenario A**: ≥3 cluster paths meet 10% threshold → 3 path-based reports
- **Scenario B**: 2 paths meet threshold → 2 path-based + 1 feature-based report
- **Scenario C**: 1 path meets threshold → 1 path-based + 2 feature-based reports
- **Scenario D**: 0 paths meet threshold → 3 feature-based reports

**Prompt Location**: Generated by `build_phase2_prompt()` in `stage7_prompts.py:603`

**Key Sections**:
1. Context - Video count, unique paths, scenario
2. Phase 1 Window Analyses Summary - Condensed cluster descriptions
3. Cluster Path Analysis - Top paths with 10% threshold labels (✅/❌)
4. Scenario-Specific Instructions - How many path-based vs feature-based reports
5. Pre-Generated Feature Reports (Scenarios B/C/D) - Python-generated fallback reports
6. Universal Principles (CONTRASTIVE only) - RF features that predict success across all windows
7. Cross-Window Patterns (CONTRASTIVE only) - How features change between windows
8. Output Requirements - JSON schema with exactly 3 creative reports

**Example Length**: ~15,000 characters for Scenario B in CONTRASTIVE mode

**Full Prompt**: See `/tmp/phase2_contrastive_prompt.txt`

## Current Prompt Characteristics

### Phase 1 (Window Analysis)
**CONTRASTIVE Mode**:
- Shows 10 RF features with bimodal pattern analysis
- Shows 3 K-Means clusters with high-contrast features
- Shows RF Alignment for each cluster (which features match top predictors)
- Instructs LLM to analyze ALL 3 clusters
- ~9,000 characters

**TOP Mode**:
- Shows 3 K-Means clusters only
- No RF references
- Focuses on identifying common patterns among top performers
- ~6,000 characters (shorter due to no RF sections)

### Phase 2 (Synthesis)
**Both Modes**:
- Summarizes all Phase 1 window analyses
- Shows cluster path frequency data
- Applies 10% threshold for path-based reports
- Generates feature-based fallbacks when needed
- ~15,000-20,000 characters depending on number of windows

**Key Difference**:
- CONTRASTIVE includes "Universal Principles" and "Cross-Window Patterns" sections showing RF feature trends
- TOP omits these sections (marked as "not available")
