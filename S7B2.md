## Executive Summary

**Issue**: The `supplementary_insights.cross_window_patterns` field is empty in all Stage 7 outputs, despite MLPlanningv2.md specification requiring temporal progression patterns (e.g., "Energy Crescendo" where energy builds from hook → middle → closing).

**Root Cause**: Cross-window features (e.g., `hook_to_middle_energy_delta`, `energy_progression_slope`) are created in Stage 4 for RF training but are **NOT included in Stage 3's canonical `aggregated_features.csv`**. This causes:
1. **Stage 6**: Cannot compute distributions (features only in `rf_transformed.csv`, not `aggregated_features.csv`)
2. **Stage 7**: Cannot generate patterns (no valid distribution data to analyze)

**Impact**: Missing 30% of actionable insights - creators don't learn about temporal progressions like "energy should build throughout video"

**Fix Strategy**: ✅ **ROOT CAUSE FIX** - Move cross-window feature generation AND is_top_performer label from Stage 4 to Stage 3
- Cleaner architecture (single source of truth for features AND labels)
- Works for ALL modes (contrastive AND top)
- Works for ALL buckets (including short-duration)
- Future-proof (no brittle string matching)
- Eliminates Stage 6 dual-source complexity

**Estimated Effort**: 12-16 hours (6-8h Stage 3, 2-3h Stage 4 cleanup, 1h Stage 6 validation, 3-4h testing + fixtures)

```python
def add_cross_window_features(df: pd.DataFrame, bucket: str) -> pd.DataFrame:
    """
    Compute cross-window derived features after base aggregation.

    Cross-window features represent relationships BETWEEN temporal windows
    (e.g., energy change from hook to middle, overall energy trend, consistency metrics).

    Args:
        df: DataFrame with base temporal features (varying by bucket)
        bucket: Duration bucket (determines which windows exist)

    Returns:
        DataFrame with 0-5 additional cross-window features (bucket-dependent)

    Features Added (when applicable):
        1. hook_to_middle_energy_delta: Energy change from hook to middle average
        2. middle_to_closing_delta: Energy change from middle average to closing
        3. eye_contact_consistency: Std deviation of eye_contact_rate across windows
        4. word_density_std: Std deviation of word_count across windows
        5. energy_progression_slope: Linear regression slope across all windows

    Bucket-Specific Behavior:
        - 0-3s: 0 features (only hook, no comparisons possible)
        - 3-9s: 3 features (hook + closing: consistency metrics + slope, no deltas)
        - 9-13s, 13-18s: 5 features (handles middle_aggregate correctly)
        - 18-33s+: 5 features (full feature set)

    Source: S7B2.md Root Cause Fix
    """
    import numpy as np
    from scipy import stats
    from config.bucket_definitions import BUCKET_WINDOWS

    logger.info(f"Computing cross-window features for bucket {bucket}...")

    # Get actual window names for this bucket (handles middle_aggregate)
    windows = BUCKET_WINDOWS[bucket]

    # Identify existing windows from column names
    has_hook = 'hook_energy_level' in df.columns
    has_closing = 'closing_energy_level' in df.columns

    # CRITICAL: Handle middle_aggregate for buckets 9-13s, 13-18s
    middle_energy_cols = [f'{w}_energy_level' for w in windows if w.startswith('middle')]
    has_middle = len(middle_energy_cols) > 0

    cross_window_count = 0

    # Feature 1: Hook to Middle energy delta
    # Only compute if both hook and middle exist
    if has_hook and has_middle:
        df['hook_to_middle_energy_delta'] = (
            df[middle_energy_cols].mean(axis=1) - df['hook_energy_level']
        )
        cross_window_count += 1
        logger.debug("  ✓ Computed hook_to_middle_energy_delta")

    # Feature 2: Middle to Closing energy delta
    # Only compute if both middle and closing exist
    if has_middle and has_closing:
        df['middle_to_closing_delta'] = (
            df['closing_energy_level'] - df[middle_energy_cols].mean(axis=1)
        )
        cross_window_count += 1
        logger.debug("  ✓ Computed middle_to_closing_delta")

    # Feature 3: Eye contact consistency (std deviation across all windows)
    eye_contact_cols = [f'{w}_eye_contact_rate' for w in windows]
    if len(eye_contact_cols) >= 2:  # Need at least 2 windows for std
        df['eye_contact_consistency'] = df[eye_contact_cols].std(axis=1)
        cross_window_count += 1
        logger.debug("  ✓ Computed eye_contact_consistency")

    # Feature 4: Word density std (pacing variability)
    word_count_cols = [f'{w}_word_count' for w in windows]
    if len(word_count_cols) >= 2:
        df['word_density_std'] = df[word_count_cols].std(axis=1)
        cross_window_count += 1
        logger.debug("  ✓ Computed word_density_std")

    # Feature 5: Energy progression slope (linear trend across windows)
    # Only compute if 3+ windows exist (need multiple points for reliable slope)
    energy_cols = [f'{w}_energy_level' for w in windows]

    if len(energy_cols) >= 3:
        # Compute linear regression slope for each video
        slopes = []
        for idx, row in df.iterrows():
            y = row[energy_cols].values
            x = np.arange(len(y))

            # Handle NaN values: skip videos with incomplete data
            if np.isnan(y).any():
                slopes.append(np.nan)
            else:
                slope, _, _, _, _ = stats.linregress(x, y)
                slopes.append(slope)

        df['energy_progression_slope'] = slopes
        cross_window_count += 1
        logger.debug("  ✓ Computed energy_progression_slope")

    logger.info(f"  Added {cross_window_count} cross-window features")

    return df
```

```python
def add_is_top_performer_label(df: pd.DataFrame, bucket_path: Path, strategy: str) -> pd.DataFrame:
    """
    Add is_top_performer column from Stage 1's selected_videos.json.

    This label indicates whether each video is in the top 80% (viral) or bottom 20% (non-viral)
    for contrastive analysis. Stage 6 needs this to compute distribution comparisons.

    Args:
        df: DataFrame with aggregated features (includes video_id column)
        bucket_path: Path to bucket directory
        strategy: "contrastive" or "top"

    Returns:
        DataFrame with added is_top_performer column (1 = top 80%, 0 = bottom 20%)

    Behavior by Strategy:
        - Contrastive: Read from selected_videos.json (explicit top/bottom labels)
        - Top: All videos = 1 (no bottom performers to contrast against)

    Fallback:
        - If selected_videos.json missing: Log warning + use index-based labeling (first 80% = top)
        - If video_id not found in mapping: Default to 1 (assume top performer)

    Source: S7B2.md Issue #5 - Alternative A (add to Stage 3)
    """
    import json

    logger.info(f"Adding is_top_performer labels (strategy: {strategy})...")

    if strategy == 'top':
        # Top mode: All videos are top performers by definition
        df['is_top_performer'] = 1
        logger.info("  ✓ Top mode: All videos labeled as top performers (is_top_performer=1)")
        return df

    # Contrastive mode: Read labels from Stage 1 output
    selected_videos_path = bucket_path / "selected_videos.json"

    if selected_videos_path.exists():
        try:
            with open(selected_videos_path, 'r') as f:
                selected = json.load(f)

            # Create mapping: video_id → is_top_performer
            performer_map = {
                str(v['id']): v.get('is_top_performer', True)
                for v in selected['videos']
            }

            # Map to DataFrame (graceful handling for missing video_ids)
            df['is_top_performer'] = (
                df['video_id'].astype(str).map(performer_map).fillna(1).astype(int)
            )

            # Log distribution for verification
            top_count = (df['is_top_performer'] == 1).sum()
            bottom_count = (df['is_top_performer'] == 0).sum()
            logger.info(
                f"  ✓ Loaded performer status from selected_videos.json: "
                f"{top_count} top ({top_count/len(df)*100:.1f}%), "
                f"{bottom_count} bottom ({bottom_count/len(df)*100:.1f}%)"
            )

        except Exception as e:
            logger.warning(
                f"  ⚠ Failed to read selected_videos.json: {e}. "
                f"Using fallback index-based labeling."
            )
            # Fallback: Use index-based 80/20 split
            top_count = int(len(df) * 0.8)
            df['is_top_performer'] = (df.index < top_count).astype(int)
            logger.info(f"  ✓ Fallback labeling: first {top_count} videos = top performers")

    else:
        logger.warning(
            f"  ⚠ selected_videos.json not found at {selected_videos_path}. "
            f"Using fallback index-based labeling."
        )
        # Fallback: Use index-based 80/20 split
        top_count = int(len(df) * 0.8)
        df['is_top_performer'] = (df.index < top_count).astype(int)
        logger.info(f"  ✓ Fallback labeling: first {top_count} videos = top performers")

    return df
```

```python
def generate_cross_window_patterns(window_analyses: dict, rf_video_data: dict) -> List[str]:
    """
    Extract cross-window patterns from video-level RF data.

    Uses explicit feature list (no brittle string matching).
    """
    # Explicit allowlist of known cross-window features
    # Source: Stage 3 adds these features to aggregated_features.csv
    CROSS_WINDOW_FEATURES = {
        'hook_to_middle_energy_delta': 'Energy increases from hook to middle',
        'middle_to_closing_delta': 'Energy continues building to closing',
        'energy_progression_slope': 'Overall energy trend across video'
    }

    patterns = []

    # Filter to cross-window features (explicit, not keyword-based)
    for feature_data in rf_video_data.get('feature_importance', []):
        feature_name = feature_data['feature']

        # Skip if not a known cross-window feature
        if feature_name not in CROSS_WINDOW_FEATURES:
            continue

        # Skip if null data (graceful degradation)
        if feature_data.get('top_performer_avg') is None:
            continue

        # Get pre-defined interpretation
        interpretation = CROSS_WINDOW_FEATURES[feature_name]
        top_avg = feature_data['top_performer_avg']
        bottom_avg = feature_data['bottom_performer_avg']
        gap = feature_data['gap']
        importance = feature_data['importance']

        # Generate pattern string
        pattern = (
            f"{interpretation}: "
            f"top performers avg {top_avg:.2f}, "
            f"bottom performers avg {bottom_avg:.2f} "
            f"(gap: {gap:.2f}, RF importance: {importance:.3f})"
        )

        patterns.append(pattern)
        logger.debug(f"Generated pattern: {pattern}")

    if not patterns:
        logger.warning(
            "No cross-window patterns generated. "
            "This may indicate: (1) short bucket with limited windows, "
            "(2) top mode with no RF training, or (3) Stage 3 not updated."
        )

    return patterns
```

- ✅ No keyword matching (explicit list)
- ✅ Pre-defined interpretations (no complex formatting logic)
- ✅ Easy to extend (just add to dictionary when Stage 3 adds features)
- ✅ Clear error messages (helps debug if patterns still empty)

## Breaking Changes Fixed (Critique Summary)

This section documents the 7 critical breaking changes identified during comprehensive critique and resolved in the final specification.

### Issue #1: Stage 3 Column Count Validation Failure
**Problem**: `EXPECTED_FEATURE_COUNTS` hardcoded to 129 for bucket 18-33s, but fix adds +5 cross-window + +1 label = 135.
**Impact**: Stage 3 validation throws `AssertionError: expected 129, got 135` → Pipeline stops.
**Fix**: Added `get_stage3_expected_feature_count()` to `config/bucket_definitions.py` (single source of truth). Computes expected count dynamically: bucket 18-33s = 135 (21×6 + 3 + 5 + 1).

### Issue #2: Stage 4 Input Validation Rejects Stage 3 Output
**Problem**: Stage 4's `validate_input()` expects 129 columns, Stage 3 now outputs 135.
**Impact**: Stage 4 throws `ValueError: Expected 129 columns, found 135` → Pipeline stops.
**Fix**: **Removed `EXPECTED_INPUT_COLUMNS` dict entirely** from Stage 4. Updated `validate_input()` to import and call `get_stage3_expected_feature_count()` from config (true single source of truth).

### Issue #3: Stage 4 Column Count Formula Double-Counts Cross-Window
**Problem**: Formula adds +5 for cross-window BUT input already has them from Stage 3.
**Impact**: Output has 150 columns instead of 146 → Stage 5 schema validation fails.
**Fix**: Updated `get_expected_video_rf_column_count()` to call `get_stage3_expected_feature_count()` from config, then apply transformation: `input - 4 dropped + 15 added` (e.g., 135 - 4 + 15 = 146 for 18-33s). True Alternative A - single source of truth.

### Issue #4: S7B2 Specification Incomplete - Missing 2 of 5 Features
**Problem**: Initial spec only showed 3 cross-window features (deltas, slope), missing `eye_contact_consistency` and `word_density_std`.
**Impact**: Stage 7 only finds 3 patterns instead of 5 → 40% of insights lost.
**Fix**: Updated `add_cross_window_features()` to compute ALL 5 features matching current Stage 4 logic.

### Issue #5: FATAL - Missing is_top_performer Column (Stage 6 Crash)
**Problem**: Stage 6 needs `is_top_performer` to compute distributions, but Stage 3 doesn't create it (Stage 4 does).
**Impact**: Stage 6 crashes immediately with `KeyError: 'is_top_performer'` → FATAL, pipeline stops.
**Fix**: **Alternative A (APPROVED)**: Added `add_is_top_performer_label()` to Stage 3, reads from `selected_videos.json`.

- Fallback: Index-based 80/20 if selected_videos.json missing
- Stage 4: Remove duplicate is_top_performer creation logic

### Issue #6: middle_aggregate Column Name Mismatch
**Problem**: Initial code used `middle_1_energy_level` but buckets 9-13s/13-18s have `middle_aggregate_energy_level`.
**Impact**: `KeyError` or empty list → `hook_to_middle_energy_delta` = NaN for 2 buckets.
